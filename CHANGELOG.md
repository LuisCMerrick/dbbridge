# Changelog

The version of a build is set when it is built (`dbbridge version`).

## [1.5.26.10.27] - 2026-10-27

Protocol 1.5, wire-compatible with 1.5.26.10.25 nodes. Data-plane performance work from the optimization review, and a stall fix.

- **Fix: 5 s stall after a server-side close.** When the backend closed a connection first (HTTP `Connection: close`, short-lived connections), the egress could drop the carrier before the ingress saw the acknowledgement of its upstream FIN; the ingress counted that normal close as a carrier failure and cooled the endpoint transport for `failover.cooldown` (5 s), so the next new session waited about 5 s. In a loopback test about one in three short connections was affected. The ingress now confirms the close over the control channel whenever either FIN acknowledgement is still missing, as it already did for the downstream one.
- **Upstream digest verified once.** An upstream frame was hashed (SHA-256) up to three times on the egress (WebSocket decode, the transport handler, and again inside the session under its lock). It is now verified once per transport, outside the session lock, and the session adopts the transport's buffer instead of copying it.
- **Downstream frames encoded with one copy.** The egress sender reads frames as views of the session window and encodes them straight into the WebSocket frame or the SSE event (SHA-256 and Base64 streamed over the segments), instead of first copying each frame out of the window. SSE events are built as one byte buffer without `fmt`/string concatenation.
- **Ingress buffers.** Local-socket read buffers are recycled by power-of-two size class (a buffer whose HTTP send failed is never recycled); WebSocket frames are written as header plus payload through one message writer instead of being joined first; SSE frame lines are buffered at their declared size instead of growing by appends.
- **Egress backend reader** blocked on the global payload budget now waits on the budget's release notification (with a 250 ms safety poll) instead of polling every 10 ms.
- **Benchmarks.** `BenchmarkByteWindowDownstream`, `BenchmarkIngestUpFrame` and the loopback end-to-end `BenchmarkForward` (ws, http-sse). Loopback, 2 vCPU arm64, before → after: http-sse 140 → 250 MB/s with 54% fewer bytes allocated; ws throughput unchanged (≈280 MB/s, bound by SHA-256 and syscalls) with 45% fewer bytes allocated; upstream ingest of a 64 KiB frame 140 → 65 µs.
- **Docs.** Capacity planning describes when and how to set `GOMEMLIMIT` (not set by default).

Codec budget charges are unchanged (conservative): the new paths use less memory than they reserve.

## [1.5.26.10.25] - 2026-10-25

Protocol 1.5, compatible with 1.5.26.10.24 nodes. Fixes from the 1.5.26.10.24 audit and shutdown review.

- **Security fix (audit AUD-01).** A reverse tunnel handshake authenticated just before a credentials reload rotated its token could still register after the reload's check. Registration now re-checks the token under the hub lock, so it is refused (`401`).
- **Fix (AUD-02, AUD-08).** Tunnel memory is now charged per open stream (a stream receive window: codec_buffer_limit/128, 256 KiB–1 MiB) instead of a whole receive buffer per idle tunnel, and the smux session bucket is sized for 1024 full windows. Idle tunnels no longer exhaust a small codec budget (two tunnels with `codec_buffer_limit: 2MiB` could not carry a first session), tunnel charges never take the local ingress reserve, and slow data streams can no longer stall a tunnel's control streams. The database side's `check-config` requires room for two stream windows (and an HTTP carrier unless `reverse.transport: ws`).
- **Fix (AUD-03).** `/v1/reverse/...` requests now go through admission: handshakes, opens and closes take a control request slot, uploads a data request slot, each with request metadata and a fair share per reverse peer; upload bodies are charged to the codec budget. Exhausted budgets answer a retryable `429`/`503`.
- **Fix (AUD-04).** `install` now snapshots `reverse.token_env` and includes `reverse.token_file` and `reverse.tls.ca_file` in the service file access checks (and the systemd sandbox paths).
- **Fix (AUD-05).** Reverse peers that share a token are told apart by the node ID their tunnel presents (it was the last match in ID order, refused with `403 DBB_NODE_MISMATCH`); HTTP tunnel requests are bound to the tunnel's own token. Reverse peers must now have distinct `expected_node_id`.
- **Fix (AUD-07).** Closing a reverse WSS tunnel closes the socket first, so a blackholed carrier no longer blocks reconnects and teardown for 5 s on TLS close_notify.
- **Fix (AUD-09).** An HTTP tunnel upload whose offset plus length overflows is refused as an offset gap instead of being taken as an empty retransmission.
- **User-Agent is configurable.** New `transport.user_agent`; every request and WebSocket handshake sent to a peer (reverse tunnels included) now carries it instead of Go's `Go-http-client/1.1`/`2.0`. Default `DBBridge/1.5`. Printable ASCII, at most 256 bytes.
- **Shutdown progress.** A stop that waits for open sessions (`transport.shutdown_timeout`, 30 s by default; pooled database connections usually keep it waiting the full time) now logs what it waits for at once and every 5 s, with the time left and a reminder that a second Ctrl-C forces the exit, and logs how many sessions it closes when the wait times out. Before, a first Ctrl-C looked like a hang.
- **Fix.** A health-check probe that never left this node (it timed out waiting for a local connection or request budget) was recorded as an endpoint failure, so local contention could mark a healthy endpoint UNHEALTHY and put it in cooldown. Local resource errors no longer change endpoint health.
- **Tests.** `TestLargeBidirectionalByteStream` bounds progress per block instead of the whole 50 MiB transfer at 15 s, so race builds on slower machines no longer fail a correctness test on throughput.

## [1.5.26.10.24] - 2026-10-24

Protocol 1.5. **Incompatible with 1.4:** both nodes must be upgraded together; a 1.4 node is answered with `DBB_PROTOCOL_MISMATCH` and the WebSocket subprotocol is now `dbbridge.v1.5`.

- **Reverse mode configuration.** New `peers[].mode` (`forward`, default, or `reverse`) and a top-level `reverse` section (`enabled`, `peer_node_id`, `token_file`/`token_env`, `transport` `auto|ws|http-sse|long-poll`, `tunnels_per_endpoint`, `endpoints`, `reconnect.min_backoff`/`max_backoff`, `tls`, `allow_insecure_http`) with defaults and validation. A node may mix forward and reverse peers. `check-config` reports new stable codes `DBB-CFG-007` (peer mode) and `DBB-CFG-008` (reverse section), both exit status 78, and warns when `recovery.grace` cannot cover a tunnel reconnect.
- **WebSocket reverse tunnels.** The database-side node dials `GET /v1/reverse` (subprotocol `dbbridge.reverse.v1.5`) and keeps `tunnels_per_endpoint` tunnels per endpoint, by priority, reconnecting at once and then with exponential backoff and jitter. Streams are multiplexed with smux v2 (new dependency `github.com/xtaci/smux` v1.5.57); each stream is a connection to the egress HTTP server, so sessions, probes, failover and recovery are unchanged, and the database side needs no listening socket. Both directions verify node identity; the public side checks the token in constant time and refuses impersonation (`403 DBB_NODE_MISMATCH`), duplicate tunnel IDs and a second live instance (new code `409 DBB_TUNNEL_CONFLICT`), and closes tunnels whose token a credentials reload rotated or revoked. Tunnel streams share the inbound connection budget and are counted per tunnel instead of per IP; tunnel receive buffers are charged to the codec budget (per stream since 1.5.26.10.25).
- **SSE and long-polling reverse tunnels.** `reverse.transport: http-sse` and `long-poll` carry the smux byte stream over plain HTTPS requests that the database side sends: `POST /v1/reverse/{tunnel}/open`, `POST …/up` (offset plus SHA-256, retried and de-duplicated) and `GET …/events` (SSE) or `GET …/poll` (long polling, about 25 s). Both sides keep unacknowledged bytes and resend them, so a dropped HTTP connection neither loses nor duplicates data and does not end the tunnel. Requests are bound to the opening token and instance; new code `404 DBB_TUNNEL_NOT_FOUND` for a tunnel the public side no longer holds. `auto` now falls back WebSocket → SSE → long polling per endpoint (on non-DBBridge answers such as redirects, 404, 426, gateway errors, or on an SSE stream whose first event does not arrive within `transport.ws.handshake_timeout`; never on 401, a DBBridge 403 or a network error) and retries WebSocket after 10 minutes. A WebSocket handshake that reaches the public side without its upgrade is now answered `426 DBB_TRANSPORT_UNSUPPORTED` (was `400 DBB_BAD_FRAME`).
- **Reverse mode tooling and observability.** `dbbridge gen-config --reverse` (with `--mode a-to-b` or `b-to-a`) writes a matched reverse pair: the node with the listener becomes the public side, the node with the database dials it and opens no socket. New metrics `dbb_reverse_hub_tunnels{peer,transport}`, `dbb_reverse_hub_accepted_total`, `dbb_reverse_hub_rejected_total{code}` (public side) and `dbb_reverse_tunnels{endpoint,transport}`, `dbb_reverse_tunnel_established_total`, `dbb_reverse_tunnel_lost_total`, `dbb_reverse_tunnel_dial_failures_total`, `dbb_reverse_tunnel_fallback_total{from,to}` (database side). `/readyz` on a database side served only through tunnels is `503` until a tunnel is up; the public side stays ready (a load balancer must not take away the address the tunnels dial) and lists reverse peers without a tunnel in the body. Documentation: reverse proxies (Transport §7.1), security model (Security §9), metrics, error codes and troubleshooting (Operations), deployment examples 5 and 6.
- **Fix.** The public side noticed a tunnel whose connection had failed only after the smux keepalive timeout (smux does not close a session on a read error), so it kept opening streams on a dead tunnel and reported it as live. It now ends the tunnel as soon as the connection fails.
- **Fix.** An egress WebSocket reader that got gorilla's `close sent` error (the peer's close frame arriving after this side sent its own) treated it as a framing violation and ended the session with `DBB_FRAME_CONFLICT` instead of letting it recover.
- **Fix.** A WebSocket session read that ended on a TLS record cut short by the end of the connection (a bare `unexpected EOF`, which is how a reverse tunnel stream ends) was treated as a framing violation and ended the session instead of letting it recover. A complete WebSocket message whose DBBridge frame is short is still a violation.
- **Fix.** Tunnel streams give exact write semantics: smux reports a write that hits its deadline as unsent although the queued frame is still sent, and a caller that retried the remainder put duplicate bytes on the stream. Writes are now copied and handed to smux without a deadline; a deadline only bounds the wait for the previous chunk.
- **Internals.** Peer connections are opened through a `PeerDialer` (TCP for forward peers, tunnel streams for reverse peers), with the per-peer and global connection budgets applied to both; the egress HTTP server also serves a tunnel-backed virtual `net.Listener`.

## [1.4.26.10.23] - 2026-10-23

Protocol 1.4. Maintenance and protocol hardening release.

- **SSE and carrier liveness.** SSE comments (such as proxy keep-alives) no longer count as session progress or consume event line limits. `http-sse` upstream frames now enforce `failure_detect_timeout` and remote backpressure timeouts while waiting for acknowledgement, matching WebSocket behaviour.
- **Connection pooling and flow control.** Outbound SSE subscriptions shard across up to `transport.h2_pool_size` (1–64) HTTP clients per endpoint. Ingress short reads compact their buffer allocation so small frames do not hold full-frame payload and recovery-retention budgets, and dynamic frame sizing clamps to the remaining send window.
- **Budgets and admission.** Bidirectional nodes size `codec_buffer_limit` and the local ingress codec reserve to cover SSE frame decoding alongside egress traffic. Egress session routes close HTTP/1.1 connections when rejecting requests before reading their body.
- **Configuration and credential reload.** Inline credential reloads reject added or duplicate `peers` entries (which require a restart). Inbound quota validation uses saturating addition. Disabled inline identities' token files are not required at service installation. `gen-config` rolls back newly created files if directory sync or pair publication fails.
- **Observability and service management.** Added `dbb_ingress_faults_total{source,reason}` and expanded terminal/fault reason classification for deterministic protocol refusals. WebSocket sessions closed during the HTTP 101 upgrade handoff still deliver their terminal `error` notice before closing the carrier. Windows service installation marks and verifies ownership of the Application Event Log source.
- **Release packaging and toolchain.** `scripts/build-release.sh` bundles `third_party/MODULES.txt` and dependency license files into release archives. Raised minimum Go toolchain to 1.27.3 (`GO-2026-6809`).

## [1.4.26.10.20] - 2026-10-20

First release. Protocol 1.4.

- **Roles.** One binary acts as ingress (local TCP listeners), egress (HTTP server in front of the databases) or both, as configured.
- **Carriers.** WebSocket, or HTTP POST + Server-Sent Events; `auto` falls back to SSE on the same endpoint when a proxy cannot carry WebSocket.
- **Failover and recovery.** Several endpoints per peer with priorities, health probes and cooldown of failed paths. Sessions with recovery enabled survive a carrier failure within `recovery.grace` without losing or duplicating a byte; otherwise the client connection is closed at once.
- **Security.** TLS, bearer-token identities, peer node identity check, per-identity target ACLs and quotas, CIDR allow-lists for targets, per-identity budget shares.
- **Credential reload.** Token files and credential settings are re-read every `auth.reload_interval`, on `SIGHUP` / `systemctl reload` and on `sc.exe control <name> paramchange`; disabling or removing an identity closes its sessions. Rejected reloads keep the previous credentials and are logged and exposed as metrics.
- **Bounded resources.** Memory, session metadata, connections and concurrency are budgeted; overload is answered with explicit, retryable errors.
- **Operations.** `gen-config` for matched pairs, `check-config` with stable error codes (`DBB-CFG-001` … `DBB-CFG-030`) and exit status 78 for configuration errors, service installation for systemd and Windows, loopback admin endpoint with `/healthz`, `/readyz` and Prometheus `/metrics`.
- **Release.** Packages for Linux amd64/arm64 and Windows amd64 with the license files and module list of linked dependencies, and `SHA256SUMS`; reproducible builds from `SOURCE_DATE_EPOCH`.
